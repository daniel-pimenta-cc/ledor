# iOS share extension setup

Android already receives shared URLs through the intent-filter in
`android/app/src/main/AndroidManifest.xml`. iOS needs a **Share Extension
target**, which has to be created in Xcode on a Mac. It is **not set up yet**:
`ios/` has no extension target and `ios/Runner/Info.plist` has no
`AppGroupId`. The Dart side (`ShareIntentHandler`) already runs on iOS
(`PlatformCapabilities.supportsShareIntent`) and needs no changes.

Follow the iOS section of the
[receive_sharing_intent README](https://pub.dev/packages/receive_sharing_intent#ios)
for the version pinned in `pubspec.lock` (1.8.1 at the time of writing). The
Ledor-specific values:

## Steps in Xcode (once)

1. Open `ios/Runner.xcworkspace`.
2. `File` → `New` → `Target…` → **Share Extension**, Swift. Name it e.g.
   `Share Extension`. Give it the same deployment target as `Runner`.
3. In **Signing & Capabilities** of **both** `Runner` and the extension: same
   Team, add the **App Groups** capability with one shared group, e.g.
   `group.com.pimenta.ledor` (the app bundle id is `com.pimenta.ledor`).
4. In **Build Settings** of both targets, add a user-defined `CUSTOM_GROUP_ID`
   set to that group id.
5. Replace the extension's `Info.plist` with the one from the package README.
   Keep only the activation rules Ledor handles (it imports URLs only):
   `NSExtensionActivationSupportsWebURLWithMaxCount = 1` and
   `NSExtensionActivationSupportsText = true`.
6. In `ios/Runner/Info.plist` add `AppGroupId = $(CUSTOM_GROUP_ID)` and a
   `CFBundleURLTypes` entry with scheme `ShareMedia-$(PRODUCT_BUNDLE_IDENTIFIER)`
   (the extension uses it to open the host app).
7. In `ios/Podfile` (generated by the first iOS build), nest a
   `target 'Share Extension' do inherit! :search_paths end` block inside
   `target 'Runner'`.
8. Make `ShareViewController` inherit from `RSIShareViewController`
   (`import receive_sharing_intent`). Keep the default auto-redirect, so the
   app opens and starts the import.
9. In `Runner` → **Build Phases**, move **Embed Foundation Extension** above
   **Thin Binary** (otherwise: "No such module 'receive_sharing_intent'").

## Testing

1. `flutter run` on a physical device or TestFlight build (the simulator share
   sheet doesn't list third-party extensions).
2. In Safari, share a page; Ledor should appear as a target.
3. Pick it: the app opens, the "Fetching article…" snackbar appears and the
   reader opens when the import finishes (see
   [article-import.md](article-import.md)).

## Why it isn't scripted

A share extension is a separate Xcode target with its own files (`Info.plist`,
`.entitlements`, `ShareViewController.swift`) plus capability setup (App Groups
+ Team). Generating it would mean editing `project.pbxproj` by script, which is
fragile; do it once in Xcode and commit the result.
